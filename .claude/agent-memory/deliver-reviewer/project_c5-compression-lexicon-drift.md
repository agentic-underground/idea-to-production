RFC context-routing.md §6 "C5 — tighten the always-on catalog" is being rolled out per-plugin (§7 covers all eight; slice 2 = discover+ideate, PR #272). Each slice compresses `description:` frontmatter to ≤60w/≤400c: capability → `Trigger with /cmd (or "phrase",…)` → `Guard:` (C1) → `→ output`.

**Recurring drift class to attack on every C5 slice:** compression drops a trigger phrase that `docs/guide/lexicon.md` §4 (collision families) or §2 still advertises for that skill — sensor-level drift the routing gate does NOT catch (R8 syncs family-ids only; §2/§4 phrases are maintainer-asserted, checked only by the opt-in Layer-2 eval).

**Why:** the lexicon is a user-facing promise ("say this → loads that"). Slice 2 examples: ideate:ideate dropped "I have an idea: …" though §4 C0-idea-intake names ideate:ideate for it (mitigated — deliver:ideate fallback still carries it); the raw-thesis triad "By doing X I propose Y, value Z" left both discover:market-scan and ideate:ideate sensors (survives only in bodies + i2p:help). Both LOW in slice 2 because fallbacks/bodies retain them.

**How to apply:** when reviewing any C5 slice, diff the RETAINED trigger phrases against lexicon §4 family rows + §2 for those skills; flag any phrase the lexicon still promises but the compressed sensor no longer carries. Also confirm cross-cut skills (self-improve/check) correctly OMIT the Guard clause (§3.1 exempts them) — not a defect. See [[i2p-command-stutter-rename]] for the sibling rename-wave prose-drift class.
