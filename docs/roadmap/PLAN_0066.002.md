**Brief**: A pre-push gate that fails a branch/PR with no board linkage, honouring the logged
`[no-board]` exemption. Deterministic offline for the declaration; best-effort online (via `gh`) for
existence on project #4 — degrading gracefully when `gh`/network is absent, in the house style of the
other `verify-*` checks.

## User stories
- AS the builder I WANT the pre-push gate to refuse un-linked substantive work SO THAT the
  context-routing-style off-board drift cannot recur silently.

## EARS specification
- **EARS-001** (Event-driven) — WHEN the linkage gate runs on a branch, it SHALL PASS iff the branch
  declares a board item (a `Board: #<n>` or `Refs #<n>` commit/PR trailer OR a `pipeline/NNNN-*` branch
  name) OR carries a `[no-board]: <reason>` logged exemption; otherwise it SHALL FAIL.
- **EARS-002** (State-driven) — WHILE `gh` is available and authenticated, the gate SHALL verify the
  declared issue exists on project #4; WHILE it is not, the gate SHALL degrade to declaration-only
  (advisory note), never a false PASS by silence.
- **EARS-003** (Ubiquitous) — the gate SHALL run offline for the declaration check (no network needed to
  block an un-declared branch).
- **EARS-004** (Unwanted) — IF the branch is the default branch (`main`) or a detached state, THEN the
  gate SHALL no-op (linkage is a per-feature-branch contract).

## Acceptance criteria
1. Given a branch with a `Board: #123` trailer, When the gate runs, Then it PASSes (declaration present).
2. Given a branch with neither trailer/branch-name nor exemption, When the gate runs, Then it FAILs
   (exit 1) with a message naming the fix.
3. Given a `[no-board]: typo fix` marker, When the gate runs, Then it PASSes and prints the logged reason.
4. Given `gh` unavailable, When the gate runs on a declared branch, Then it PASSes with an advisory
   "existence unverified (offline)" note — not a failure.

## Human interface test plan
None — a shell gate. Proof: unit-style fixtures (a fake branch/commit set) exercise each acceptance
row; the gate mirrors `verify-routing.sh` house style (section/pass/fail, `exit 0|1`).

## Implementation notes
- New `scripts/verify-board-linkage.sh`, wired into `.pipeline/verify` (pre-push, per "gates not CI").
- Parse the convention defined by PLAN 0066.001. Use the safe `IFS`/`read -ra` idioms (the slice-4 R7
  lesson — no word-split/glob on derived values).
- Best-effort existence: `gh issue view <n> --json projectItems` (or `gh project item-list 4`) guarded by
  `command -v gh` + a fast auth probe; timeouts short; failure → advisory, not fatal.
- Threshold: the `[no-board]: <reason>` exemption is the calibrated escape hatch (require + logged).

## Construction process
Test-first: author the gate's fixtures + the 4 acceptance rows, then the script, drive to green; wire
into `.pipeline/verify`; verify the whole gate stays green on a properly-linked branch. PR linked to
this issue, `/deliver:pr-review` (CORRECTNESS + SECURITY for the shell + `gh` calls), self-merge on PASS.

- `.pipeline/verify` + `verify-prereqs.sh` GREEN; adversarial review PASS.
