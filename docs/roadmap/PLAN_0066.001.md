**Brief**: Make the board the documented first step for substantive work, and define the one linkage
convention every downstream guardrail reads. Amend `CLAUDE.md`'s GIT WORKFLOW to add step 0 (capture on
the board first) and specify the convention; establish `docs/roadmap/` (absent today) with this EPIC's
on-disk docs.

## User stories
- AS the marketplace's builder I WANT the documented workflow to start on the board SO THAT substantive
  work is captured as an EPIC/PLAN before it is built, not after.
- AS a downstream guardrail (gate, tripwire, template) I WANT one canonical linkage convention SO THAT
  I can check the same thing everywhere.

## EARS specification
- **EARS-001** (Ubiquitous) — CLAUDE.md SHALL document a board-first step 0: substantive work is captured
  as a board EPIC/PLAN (via `/deliver:roadmapper`) before a branch is cut.
- **EARS-002** (Ubiquitous) — CLAUDE.md SHALL define the linkage convention: a `Board: #<issue>` (or
  `Refs #<issue>`) commit/PR trailer OR a `pipeline/NNNN-*` branch name, and a `[no-board]: <reason>`
  logged exemption for trivial work.
- **EARS-003** (Ubiquitous) — the repository SHALL contain `docs/roadmap/` with `EPIC_0066.md` and this
  EPIC's PLAN docs, matching the FLEET v2 grammar (`verify-prereqs.sh` Check P stays green).
- **EARS-004** (Unwanted) — IF a change is trivial (typo/formatting/one-line chore), THEN the convention
  SHALL permit a logged `[no-board]` exemption rather than forcing an EPIC/PLAN (`muri` avoidance).

## Acceptance criteria
1. Given CLAUDE.md, When read, Then the GIT WORKFLOW lists a board-first step 0 and the exact linkage
   convention (trailer, branch form, exemption form).
2. Given `docs/roadmap/`, When listed, Then `EPIC_0066.md` + `PLAN_0066.00N.md` exist and conform to the
   FLEET v2 grammar (Metadata `**Branch**` scrape; `## Plans` grammar).
3. Given `bash scripts/verify-prereqs.sh`, When run, Then Check P is GREEN with the new docs present.

## Human interface test plan
None — documentation + repo-structure change. Proof: `verify-prereqs.sh` Check P green with the new
`docs/roadmap/` tree; a reviewer confirms CLAUDE.md states the convention unambiguously.

## Implementation notes
- Edit `CLAUDE.md` → GIT WORKFLOW: insert step 0; add a "board linkage" subsection stating the trailer /
  branch / exemption forms and the trivial-work threshold.
- Create `docs/roadmap/EPIC_0066.md` + `PLAN_0066.001..004.md` (this EPIC's docs), Phase+Loads tags per

## Construction process
A docs/structure slice — no code. Author CLAUDE.md step 0 + convention and the `docs/roadmap/` docs on a
branch, verify `verify-prereqs.sh` + `.pipeline/verify` green, PR linked to this issue (`Board: #<this>`),
`/deliver:pr-review`, self-merge on PASS (direct-merge governance).

## Definition of done
- CLAUDE.md documents step 0 + the linkage convention + the logged-exemption threshold.
- `docs/roadmap/` established; `verify-prereqs.sh` Check P + `.pipeline/verify` GREEN.
- Adversarial review PASS.
