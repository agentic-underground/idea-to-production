# PR template + CI backstop for board linkage

**Brief**: GitHub-native reinforcement — a PR template with a required `Board: #___` field, and a CI job
that fails a PR whose body declares no valid board reference (and no logged exemption). CI is the
*backstop*, not the primary gate (pre-push is), so it stays lightweight.

## User stories
- AS a reviewer I WANT every PR to state its board item up front SO THAT linkage is visible at review
  time and enforced even if a pre-push gate was skipped.

## EARS specification
- **EARS-001** (Ubiquitous) — the repository SHALL ship `.github/PULL_REQUEST_TEMPLATE.md` prompting for
  `Board: #<issue>` (or `[no-board]: <reason>`).
- **EARS-002** (Event-driven) — WHEN CI runs on a PR, a job SHALL FAIL the PR if its body contains
  neither a `Board: #<n>` reference nor a `[no-board]: <reason>` marker.
- **EARS-003** (Ubiquitous) — the CI job SHALL be the *backstop*; the authoritative gate remains the
  pre-push `verify-board-linkage.sh` (PLAN 0066.002).

## Acceptance criteria
1. Given a new PR, When opened, Then the template pre-fills the `Board:` prompt.
2. Given a PR body with `Board: #123`, When CI runs, Then the linkage job passes.
3. Given a PR body with neither reference nor exemption, When CI runs, Then the linkage job fails.
4. Given a PR body with `[no-board]: <reason>`, When CI runs, Then the job passes and surfaces the reason.

## Human interface test plan
None — a template + CI YAML. Proof: the linkage-check script the CI job runs is exercised by fixtures
(PR-body strings) covering the four rows; the template renders on PR creation.

## Implementation notes
- `.github/PULL_REQUEST_TEMPLATE.md` with the `Board:` section + a one-line convention pointer.
- Extend `.github/workflows/verify.yml` with a `board-linkage` job that reads the PR body (via the event
  payload) and runs the same check logic as the pre-push gate — reuse, don't duplicate (call
  `scripts/verify-board-linkage.sh` in a `--pr-body <file>` mode, or a thin shared helper).
- Keep it fast; it is a backstop, not the primary enforcement.

## Construction process
Author the template + the CI job + the shared check-body mode + fixtures; verify on a test PR body; PR
linked to this issue; `/deliver:pr-review`; self-merge on PASS.

## Definition of done
- `.github/PULL_REQUEST_TEMPLATE.md` prompts for the board item.
- CI `board-linkage` job passes/fails per the four rows; reuses the pre-push gate logic.
- `.pipeline/verify` GREEN; adversarial review PASS.
